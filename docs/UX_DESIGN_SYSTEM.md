# Crosspost UX 2.0 — дизайн-система

Статус: визуальное направление согласовано, точные компоненты и макеты проверяются в UX-00. Не готовый интерфейс. См. [UX_ROADMAP.md](UX_ROADMAP.md).

## Визуальные принципы
Mobile-first, минимум обязательных действий, спокойный фон, один основной акцент, понятные названия на русском. Существующая функциональность не исчезает при упрощении. Без декоративных анимаций и аналитики без пользовательской задачи.

| Токен | Начальная спецификация |
|---|---|
| Фон light / dark | #F5F6FA / #10141C |
| Поверхность light / dark | #FFFFFF / #202838 |
| Основной текст light / dark | #182030 / #F1F5F9 |
| Акцент | #4F46E5; светлый вариант для текста на тёмном фоне #A5B4FC |
| Статусы | успех зелёный, ожидание нейтральный/синий, внимание янтарный, сбой красный; текст и значок обязательны |
| Шрифт | Inter или системный sans-serif, локальная/системная загрузка; 16 px основной |
| Отступы | 4/8/12/16/24/32 px |
| Радиус | 8–12 px |
| Интерактивность | цель 44×44 CSS px; анимация 120–200 мс, reduced-motion |
| Темы | системная по умолчанию, светлая/тёмная вручную |

Цвета — отправная точка; проверять контраст WCAG 2.2 AA, особенно вторичный текст, состояния и кнопки. Не кодировать состояние только цветом. Не копировать интерфейсы сторонних сервисов. Общие компоненты: Button, Input, Select, Dialog, Alert, Status, Empty/Error/Loading, MediaPicker, TargetPicker, DateTimePicker, PostCard, Navigation. Доступные label, focus-visible, клавиатура, dialog focus trap/restore, aria-live для прогресса/результата, понятные ошибки у поля. Никакой блокировки zoom. Навигация, клавиатура и safe-area на телефонах.

## Экраны и состояния
- Обзор: основное действие «Создать пост», ближайшие события, реальные счётчики и требующие внимания. Никаких фиктивных метрик.
- Редактор: поле текста и медиа, выбранные цели с именами, причины недоступности, локальное время/зона, приблизительный предпросмотр (явно обозначен), одна главная кнопка. Дополнительные настройки раскрываются.
- Календарь: неделя/месяц/список, дата, фильтры, карточки с платформой и статусом, доступный перенос.
- История: список/поиск, раскрытие поканальных результатов, причина и допустимое действие; ссылки только если подтверждены данными.
- Клиенты/модерация: видимый контекст клиента, предпросмотр, одобрить/отклонить с причиной, ограничения действий из серверного состояния.
- Подключения: карточка платформы, состояние и следующее действие, существующий мастер; продвинутые настройки по запросу.
- Медиа: сетка/список, название/тип/размер, предпросмотр, повторное использование; без удаления до T-214.
- Каждый экран: loading, empty (только после успешной загрузки), error с retry чтения, stale с предупреждением, permission denied, session expired с сохранением допустимого черновика.
- Подтверждение только для опасных действий, неоднозначного результата и важных смен контекста; не добавлять обязательный шаг к обычному посту.

## Техническая структура
Постепенно выделять shared/, styles/, components/, features/editor/, features/calendar/, features/publications/, features/media/, features/connections/, features/moderation/, admin/, client/ в существующем web/frontend. Сохранить доступность / и /client и упаковку статических ресурсов. Общие чистые функции и API-контракты, без обязательной миграции React/Preact или сборщика; решения о консолидации по отдельному PR. Не хранить секреты в frontend. Прототип UX-00 — отдельный статический демонстратор без production API, персональных данных и реальных отправок.

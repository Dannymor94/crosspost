# T-218 — editor state and draft safety

## First slice — target selection (draft)
Both editors retain only previously selected eligible targets. No initial auto-select or automatic expansion on media/content changes. Request version fencing rejects stale target/media-preview responses. Failed target read is distinct from successful empty read; retry available and sending disabled until valid targets. Client shows removed targets. Shared browser helper regression covers intersection and fencing, not full editor E2E. Admin removed-target feedback, upload byte-limit parity and request/session teardown need follow-up.

## Draft contract (design, not implemented)
Use a scoped authenticated draft record or an explicitly limited browser-local draft, never shared global text keys. Verify account/profile incarnation, clear/revoke on logout/account switch, reject stale saves after scope changes, use revision CAS for multi-tab conflicts. Store text and selection separately from actual media; never claim local file restoration. Do not persist signed/private URL tokens in local storage. If a selected file or URL cannot be recovered, show explicit required reselection and prevent silent text-only send. Save status only after durable successful write; debounce with final flush strategy, quota/network error and unsaved state. A successful send clears only the exact submitted revision; unknown operation must retain draft and T-216 recovery. No server schema, browser persistence or auth changes in first slice. Separate QA required; reconcile with T-215/216/217 before activation.

## Second slice — server draft storage (draft)
New authenticated scoped draft resource, no browser text persistence, revision CAS with immutable random revision and tombstone on clear. Account/profile incarnation includes creation timestamps, role, profile assignment and password hash; password rotation intentionally invalidates prior draft access. Client cannot access admin draft for same profile. No media bytes, paths or explicit media URLs stored; only media-required marker. GET/PUT no-store. Existing stateless session revocation/ID reuse limitations remain dependent on auth tasks; server drafts persist after logout but are unavailable without authorized login. Old inaccessible scope retention/purge needs owner policy. New migration currently branches from t203_fencing; reconcile after T-217 before merge. UI wiring and tests of actual editor lifecycle pending. CI pending.

## Third slice — editor autosave (draft)
Both editors use a shared hook with authenticated server read, 450ms debounce, single in-flight write, revision acknowledgement and conflict state. Draft loading blocks editing; save error/conflict blocks sending; text, post/article fields and targets restored, client schedule wall input restored. Media marker only; reselection or explicit removal required. No local text/URL storage. Unload, main tab/profile changes and logout warn on unacknowledged edits. GET binds expected actor, PUT scope binds account/profile; unmount aborts requests. Exact submitted-revision clearing and T-216 recovery integration remain open (immediate results do not auto-clear; reset/new-post explicitly clears editor; admin schedule reset inherited). Admin schedule modal time not persisted yet. Full browser E2E, all navigation/remote logout paths, server session revocation, migration chain and independent QA pending. No production changes.

## Fourth slice — exact revision clear (draft)
Only a nonempty all-DONE immediate result or explicit scheduled/pending receipt attempts CAS clear of captured scope/revision. Local text/selection or attachment changes prevent destructive hydration; newer server revisions reject clear. Unknown/partial results retain draft. Added stale-clear API and browser classification regressions. Full reload/conflict editor E2E, pending-operation guard integration and auth lifecycle remain outstanding. Fixed migration formatting; CI not yet confirmed.

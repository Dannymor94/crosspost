# ROADMAP.md — дорожная карта: продакшен, клиенты, бизнес

MVP пройден: продукт публикует в шесть каналов, умеет планировщик, импорт плана,
клиентский режим и модерацию. Следующая цель — **сервис, которому можно доверить
аккаунты многих клиентов и который работает без ноутбука владельца**.

**Правила движения:**
- Фаза закрыта, только когда выполнены **все** её критерии «Готово, когда».
- Следующая фаза не начинается, пока текущая не закрыта. Исключение — задачи P0,
  которые владелец явно поднимает раньше.
- Задачи фаз — в [`BACKLOG.md`](BACKLOG.md) (ID `T-<фаза><NN>`).

---

## Фаза 1 — Фундамент

**Зачем:** любой агент и любой чат должны получать верную картину и надёжную проверку.

- Документация перестроена: правила в `AGENTS.md`, состояние в `STATUS.md`, архив отделён.
- CI зелёный и проверяет то же, что DoD.
- Тесты герметичны, конфигурация корректно читается из окружения.

**Готово, когда:**
- CI зелёный на `main`;
- `pytest` проходит в чистом клоне без папки `runtime/`;
- приложение стартует с конфигурацией только из env (без `runtime/.env`);
- `.env.example` перечисляет ровно те переменные, что читает код.

---

## Фаза 2 — Надёжность для продакшена

**Зачем:** с реальными клиентами сбой должен обнаруживаться до публикации, а данные —
переживать обновления.

- Одна система миграций (Alembic), безопасная для базы с данными.
- Health-check сессий по расписанию: мёртвая сессия → `needs_relogin` → уведомление.
- Circuit breaker на `(profile, channel)`.
- Российский прокси для браузерных каналов ВК и Яндекса.
- Бэкап базы и vault с проверенным восстановлением.
- Удалены мёртвые заглушки.

**Готово, когда:**
- обновление схемы проходит на копии боевой базы без ручных действий;
- протухшая сессия видна в UI до того, как в неё уйдёт пост;
- забаненный канал не получает повторов;
- восстановление из бэкапа проверено и описано в `OPERATIONS.md`.

---

## Фаза 3 — Деплой на VPS вне РФ

**Зачем:** сервис работает круглосуточно и доступен клиентам с телефона.

- Docker-образ и запуск через compose или systemd.
- HTTPS и домен; публичный URL для Instagram без туннеля.
- Браузерный тир на сервере (headless или Xvfb, решение в `decisions.md`).
- Секреты из внешнего хранилища или env сервера, не из файлов в `runtime/`.
- Мониторинг и алерты владельцу: сервис упал, исполнитель планировщика стоит, растут ошибки.

**Готово, когда:**
- клиент публикует через `/client` с телефона, ноутбук владельца выключен;
- все шесть каналов проходят живой smoke с сервера;
- падение сервиса приходит владельцу алертом.

---

## Фаза 4 — Множество клиентов и бизнес

**Зачем:** подключение нового клиента — повторяемая процедура, а не ручная работа владельца.

- Регламент онбординга клиента: профиль, пользователь, подключение каналов, проверка.
- Уведомления клиенту: пост ушёл, пост упал, канал требует переподключения.
- Журнал действий (кто, что, когда) по каждому профилю.
- Лимиты на профиль (объём медиа, частота публикаций).
- Продуктовые решения владельца: тарифы, учёт, договор, политика данных.
  Каждое решение фиксируется в `decisions.md` до реализации.

**Готово, когда:**
- новый клиент подключается по регламенту из `OPERATIONS.md` за известное время;
- клиент узнаёт о проблеме с каналом сам, без владельца.

## Фаза 5 — Развитие продукта

- Разделить `index.html` на модули (снять горячую точку).
- Реальные квитанции для `yandex` и `vk_channel`.
- Автопродление токена Instagram.
- Импорт плана: при превышении лимита видео пропускать только этот канал, а не всю строку.
- Новые каналы по рецепту: YouTube, Дзен, WhatsApp; перевод ВК в API-тир при доступном user-токене.

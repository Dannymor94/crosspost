## Аудит сигналов до реализации

| Источник | Доказательство | Классификация | Действие |
|---|---|---|---|
| Telegram `publish`, подключение клиента | SDK `FloodWaitError.seconds` | RATE_LIMIT | сразу OPEN, ограниченный Retry-After |
| Telegraph HTTP, Instagram HTTP | `HTTPStatusError.response.status_code == 429` | RATE_LIMIT | сразу OPEN; числовой/HTTP-date Retry-After |
| Telegram | SDK `UserDeactivatedBanError` | BANNED | постоянный connection guard, без таймера |
| Telegram | SDK `AuthKeyUnregisteredError`, `SessionRevokedError` | AUTH | NEEDS_RELOGIN с credential fencing |
| Instagram | code 190 → `InstagramTokenError` → NEEDS_RELOGIN | AUTH | ручной вход, отдельно от breaker |
| Browser | `ResultStatus.NEEDS_RELOGIN` | AUTH | ручной вход, отдельно от breaker |
| HTTP proxy/network/timeout | тип transport/timeout | TRANSIENT | не бан и не подтверждённый лимит |
| Остальные RPCError/FAILED/ok=false/DOM | однозначного типизированного доказательства нет | UNKNOWN | не угадывать бан или лимит |
| DONE с квитанцией | явный положительный результат адаптера | подтверждённый успех | закрывает только свой epoch HALF_OPEN |
| SUBMITTED, SKIPPED без квитанции | неоднозначная доставка / checkpoint | не health-success | терминальность без пересылки, breaker не закрывать |

Telethon `flood_sleep_threshold=0` в управляемом клиенте предотвращает скрытый sleep/retry SDK до breaker.
Браузерные DOM-сигналы банов/лимитов и дополнительные неописанные коды площадок не поддержаны;
они остаются UNKNOWN. Селекторы и значения кодов не угадывались.

## Политика и ограничения

`BREAKER_COOLDOWN_SECONDS`: 300 по умолчанию, диапазон 1…86400 секунд.
`BREAKER_LEASE_SECONDS`: 600 по умолчанию, диапазон 1…3600 секунд.
Невалидное/нечисловое/NaN/бесконечное значение → безопасное значение по умолчанию;
положительное вне диапазона ограничивается. Доверенный Retry-After от явного 429/FloodWait
может продлить паузу до 86400 секунд, но не сократить настроенный cooldown.
`BREAKER_FAILURE_THRESHOLD` больше не используется: generic ошибки не являются rate limit.
В breaker хранятся только scope, состояние, счётчик, epoch и времена; секретов нет.
Времена breaker нормализуются в UTC; расписание и browser cooldown сохраняют существующую
локальную naive-конвенцию. Часы инжектируются; логика тестов не зависит от sleep.

Истёкшая HALF_OPEN lease → карантин OPEN без deadline. Вторая автоматическая проба запрещена,
поскольку таймер не доказывает завершение первой отправки. Владелец останавливает зависшую
операцию и выполняет явную успешную проверку подключения (существующее действие «Проверить»).
Epoch снимается перед проверкой; активная lease и более новый epoch не сбрасываются.
Это безопасная политика CB-09, а не автоматический crash-retry.

CB-11 использует разрешённый контрактом сериализуемый исход: первый rate-limit результат
открывает новый epoch; второй результат старого epoch явно отвергается (`settle=False`),
не перезаписывая состояние/счётчик. Тест запускает две настоящие отправки через PublishService,
наблюдает два вызова адаптера и результаты обоих settlement. Принятый счётчик атомарен в SQL.

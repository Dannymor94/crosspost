# UX-00 R3 — первый вход и self-service подключение

Owner feedback 2026-11-25: в R2 нет пути нового клиента, нужны подробные инструкции и минимум действий. Scope: design-only prototype; не дублировать открытый T-401 PR #49, T-407 invitations, T-409 auth hardening, T-406 recovery, T-410 isolation. UX-10/onboarding становится условием полноценного клиентского пилота; текущий ручной пилот регулируется T-401. Не изменяет production gates.

## Целевой сценарий
Admin creates isolated client profile and one-time invitation. Client opens HTTPS link, chooses credentials, accepts terms as applicable, enters workspace. Invite short-lived, single-use, server-side hash, atomic redemption, rate limit, revocation; role/profile determined by server, never by URL/form; owner recovery. No public open registration in this scope. Revisit separate product decision if needed. First run offers platforms, one connected target is enough, skip optional; persistent checklist and resume; connections available from client menu. Connect button opens existing declarative channel guide; one meaningful action per step, direct verified link to exact external section, inline hints, masked inputs and safe copy/paste, validation, help/error recovery, back/cancel/resume, explicit check access and target. No test post without permission; successful login is not necessarily valid publishing target. Do not solicit secrets in chat/support.

Do not expose credentials or claim ready. Instagram currently requires business account ID and long-lived access token; official OAuth redesign is optional future investigation with verified platform docs and app permissions. Telegram current flow requires api_id/api_hash, target, phone/code/optional 2FA; no Bot API substitution without separate capability/security decision. Telegraph separate account, VK wall/channel shared login but separate destinations. Actual registry may expose other entries; render from server. R3 simulates a subset, no real secrets or external network.

## Acceptance
Invite creation/redeem/reuse/expiry/revocation/concurrent redemption/foreign tenant tests; login recovery and permission checks; client can connect only own approved targets under server policy, secret redaction; connection readiness based on real validation, no fake success; resume after interrupt and cancel, accessible mobile UI. Each guide has accurate external landmarks and troubleshooting; actual iOS/Android remote authorization and platform-specific smoke required. Measure internal UX clicks separately from external platform steps: target 2–3 internal navigation actions to open wizard, not guaranteed two clicks end-to-end. Prototype is in PR #52; not security implementation. Future backend task IDs and changes to plan after coordination with existing security/ops PRs. Calendar word breaking: concise visible status with full accessible text in details, no character-level wrap.

## Подтверждённые свойства

- `web/deps.py`: `require_profile_access` проверяет `profile_id` на сервере;
  `require_admin` ограничивает административные эндпоинты. `admin` имеет доступ
  к любому профилю; `client` — только к назначенному (включая каналы/публикации).
- `db/models.py`: публикации, подключения, токены каналов и журналы привязаны
  к `profile_id`; `web/routes/users.py` создаёт client только после проверки профиля.
- `web/routes/auth.py`: login по хэшу scrypt; cookie подписана HMAC, HttpOnly,
  SameSite=Lax. Пароли площадок не должны сохраняться по инварианту AGENTS.md.
- Существующие `tests/web/test_auth_api.py` / `test_client_role.py` покрывают
  базовый сценарий: клиент A не читает B, admin видит оба.

## Границы T-406

- Новый admin-only выпуск токена требует повторного ввода пароля владельца и
  относится только к `Role.CLIENT`. Действующий
  admin может читать и обслуживать профиль без входа под логином клиента.
- Токен `recover-v1` нельзя предъявить как сессию. Он действует 15 минут,
  одноразовость обеспечена CAS по `session_generation`; аудит не содержит секрета.
- Миграция добавляет `users.session_generation DEFAULT 0`: у существующих клиентов
  сохраняется текущий вход до первого сброса.
- Клиентские аккаунты не создаются автоматически, подтверждение email/SMS
  не притворяется реализованным; личность перед выпуском подтверждает владелец.
- Ветка не включает self-registration, MFA, global CSRF/rate-limit или новый UI:
  эти изменения требуют отдельных PR и независимой QA.

# AGENTS.md — правила для всех агентов

Единая точка входа для любого агента (Codex, Claude Code и других) и любого нового чата.
Правила живут **только здесь**. Другие файлы на них ссылаются, а не копируют.

---

## 0. Протокол старта (выполнять каждую сессию, по порядку)

1. Прочитать этот файл целиком.
2. Прочитать [`docs/STATUS.md`](docs/STATUS.md): где проект сейчас, что сломано, текущий фокус.
3. Определить свою роль (§1) и выбрать/проверить назначение задачи из [`docs/BACKLOG.md`](docs/BACKLOG.md) по её ID. Если задача уже занята другим агентом — не дублировать.
4. Перед работой с кодом: `git status` и `git log -5`, чтобы убедиться, что дерево чистое
   и вы на свежем `main`.
5. Остальные документы читать **по необходимости** (таблица в §6), не все разом.

`docs/archive/` — история, не источник правды. Для работы не читать.

## 1. Роли

| Участник | Роль | Делает | Ограничение |
|---|---|---|---|
| **ChatGPT** | Главный разработчик и координатор | сам выполняет свободные задачи: код, тесты, документация, GitHub Actions; планирует и назначает остальные, ведёт Issues/PR, проверяет результаты | не дублирует уже назначенную работу; не принимает собственный код как независимый QA |
| **Claude Code** (Sonnet 4.6) и другие назначенные агенты | Исполнители | выполняют назначенные задачи, запускают DoD, делают commit/push и открывают PR | не меняют scope без записи в BACKLOG; не мержат |
| **Независимый ревьюер** (Codex/другой агент, не автор PR) | QA | проверяет diff, инварианты, тесты, CI и выдаёт вердикт в PR | не подменяет тесты отчётом автора; не пушит в ветку исполнителя |
| **Владелец** | Продуктовые решения и мерж | утверждает изменения scope/рисковые решения и мержит прошедшие проверки PR | — |

Одна задача назначается одному исполнителю; главный разработчик берёт свободную задачу либо координирует занятую. Рутинные commit, push, PR и CI не требуют повторного согласования. Независимый QA обязателен для любого кода, особенно для HIGH-риск изменений. Мерж и production-deploy остаются за владельцем до отдельного явного решения.

**Проверки запускаем по реальному прогрессу (решение владельца 2026-11-22).** Новый цикл
тестирования/независимого QA нужен после содержательного изменения поведения, кода,
миграции, конфигурации безопасности или интеграции с изменившимся `main`. Без такого
изменения **не повторять** аудит, полный прогон тестов и запросы ревью ради статуса:
сослаться на уже полученные доказательства для точного SHA/дерева. Исправление после
замечаний проверять по изменённому риску; окончательный PR с изменённым кодом по-прежнему
обязан пройти DoD, CI и независимый QA. Правка только документации проверяется по её
контракту и diff, без бессмысленного полного тестирования кода. Подробности —
[`docs/WORKFLOW.md` §2–3](docs/WORKFLOW.md).

Процесс целиком: [`docs/WORKFLOW.md`](docs/WORKFLOW.md).

## 2. Что это за продукт (коротко)

Сервис кросс-постинга для **множества клиентов**: клиент загружает готовый контент,
выбирает каналы, система публикует во все и показывает результат по каждому каналу.
Система **доставляет** контент, а не генерирует. Генерацию не добавлять.

Мы переходим от MVP к продакшену: реальные клиенты, их аккаунты и данные.
Надёжность, изоляция и предсказуемость важнее скорости новых фич.

Подробнее: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## 3. Жёсткие инварианты (нарушение = блокер на ревью)

1. **Граница API ↔ браузер.** Каждый канал по одну сторону. В `adapters/api/` нет браузерной
   логики, сессий, Playwright; импорт `sessions/` или `adapters/browser/` из `adapters/api/` запрещён.
   Один браузерный скрипт на несколько каналов запрещён.
2. **Идемпотентность по внутреннему `publication_id`**, сгенерированному до отправки.
   `external_id` — квитанция об успехе, не ключ дедупликации.
3. **Браузерный тир: verify-before-retry.** Слепой повтор запрещён: сначала проверить, не ушёл ли пост.
4. **Бан или лимит → канал не ретраить** (circuit breaker / `banned`).
5. **Сырые пароли не хранить нигде.** Релогин только руками пользователя (QR, код).
   Авто-логин паролем запрещён.
6. **Лок `(profile, channel)`** перед доступом к сессии.
7. **Медиа удалять только когда все каналы финализировались** (+ TTL).
8. **Контент рендерится под канал** и только в типы из capability-матрицы
   (`content/capabilities.py`).
9. **Частичный успех — норма.** Повторять только упавший канал, с потолком попыток.
10. **Изоляция клиентов по `profile_id`.** Каждый запрос к данным фильтрует по нему.
    Роль `client` видит только свой профиль. Новый эндпоинт без проверки доступа = блокер.
11. **Селекторы DOM и методы SDK не угадывать.** Снимать с живой страницы или читать документацию.
12. **Секреты только снаружи.** `VAULT_KEY`, `SESSION_SECRET`, `MEDIA_URL_SECRET` — из окружения.
    Нет ключа → явная ошибка, без тихого fallback. В git не попадают `runtime/`, `.env`,
    `*.session`, vault, токены.
13. **Подписанные медиа-токены не пишутся в логи целиком** (только первые 8 символов).

## 4. Конвенции

- **Mock-first.** Весь код пишется и тестируется на моках площадок. Реальные ключи нужны только
  для живого smoke, и делает его владелец.
- **TDD для логики.** Сначала падающий тест, потом код. Тесты зеркалят `src/`.
- **Исправление дефекта = исправление его класса.** Найдя дефект, проверь тот же шаблон
  во всех однотипных местах (все браузерные адаптеры, все роуты, все адаптеры канала)
  и почини везде. Тест пишется на класс проблемы, а не на один случай.
- **Новый канал = декларация + адаптер + ветка в фабрике** (`orchestrator/adapter_factory.py`).
  Рецепт: [`docs/ARCHITECTURE.md` §6](docs/ARCHITECTURE.md). Роуты, `publish_service` и фронт
  не правятся. Декларативная фабрика без ручных веток — T-506.
- **Async везде** (FastAPI, SQLAlchemy async). Синхронный I/O в event loop запрещён.
- **Одна задача = один ответственный = одна ветка = один PR.** Ветка `task/T-NNN-коротко`. Для прямого изменения регламента по запросу владельца допустима отдельная `docs/`-ветка без ID.
- **Автономная Git-рутина.** После DoD исполнитель делает commit/push и открывает PR без дополнительного запроса; GitHub Actions проверяет PR. Результаты тестов в отчёте не заменяют CI или независимый QA.
- **Коммиты:** `type(scope): что` — `feat`, `fix`, `docs`, `test`, `refactor`, `chore`.
  В теле — ID задачи (`T-NNN`).
- **Язык:** документация и UI на русском. Код, идентификаторы и сообщения коммитов —
  на английском или русском, как в окружающем коде.

## 5. Definition of Done (проверяет исполнитель до PR, ревьюер — на ревью)

```bash
ruff check src tests
ruff format --check src tests
mypy src
pytest -q
```

- [ ] Все четыре команды проходят локально; CI зелёный.
- [ ] Новый код покрыт тестами на моках.
- [ ] Инварианты §3 не нарушены.
- [ ] Изменилось поведение → обновлены `docs/STATUS.md` и `CHANGELOG.md`.
- [ ] Принято архитектурное решение → запись в `docs/decisions.md`.
- [ ] Задача в `docs/BACKLOG.md` переведена в нужный статус.
- [ ] `git status` чист от секретов.
- [ ] Горячие точки (§7) тронуты минимально.
